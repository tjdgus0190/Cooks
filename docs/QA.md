# QA 보고서 (재미 검증 + 오류 검증)

## 1. 검증 방법
| 구분 | 도구 | 내용 |
|---|---|---|
| 단위 테스트 | `npm test` (node:test, 20개) | 자유곡선 다각형 분할(면적 보존, 미관통 무시), 열전달 수치 안정성, 불 세기별 굽기 밸런스, 잔열, 평가 공식/치명적 실수 상한, 손님 선호 반영, 누락 데이터 내성 |
| 자동 플레이 | `npm run qa` (Chromium, 390×844 모바일, 터치) | 타이틀→5단계→결과 전 과정을 **실제 입력 경로**로 진행: 포인터 드래그(칼질), `DeviceMotionEvent` 주입(흔들기·휘젓기·플릭). 콘솔 에러 0건이어야 통과. 단계별 스크린샷 저장 |
| 플레이 스타일 비교 | `--style=good` / `--style=sloppy` | 숙련/대충 플레이의 점수 차로 재미(실력 반영) 검증 |
| 빌드 | GitHub Actions | Android debug APK, iOS 시뮬레이터 .app + 서명 안 된 .ipa 빌드 성공 확인 |

## 2. 재미 검증 결과
| 항목 | 숙련 플레이 | 대충 플레이 |
|---|---|---|
| 근막 제거 / 손상 | 97% / 0mm | 높은 제거율이나 궤적 흔들림 |
| 양배추 | 95조각, 가늘기 85% | 굵음 → "양배추가 너무 굵어서 질겨요" |
| 간 | 적정 근처 (소금 1.6g → "좀 싱거워요") | 과다 → "조금 짜네요" |
| 굽기 | 중심 56.7℃ 미디엄 레어, 크러스트 1.3대, 플립 19/20 (의도적 약한 첫 플립 1회 접힘) | 강불 방치 + 과한 플립 5회 모두 접힘, 크러스트 3.1 → "탄 맛이 나요" |
| **총점** | **89점 ★4 😍** | **48점 ★2 😕** |

판정:
- ✅ **실력이 점수에 반영된다** (41점 차). 실패 원인이 손님 코멘트로 구체적으로 피드백되어 다음 판에 무엇을 고칠지 명확하다.
- ✅ **회복 가능한 실패**: 플립 실패(접힘) → 탭 한 번으로 복구, 대신 시간·균일도 손해. 좌절보다 "다음엔 더 정확히"를 유도.
- ✅ **긴장 곡선**: 손질·채썰기(정밀) → 시즈닝(신체 동작, 해소) → 굽기(실시간 압박 최고조) → 플레이팅(창작, 이완) → 결과(단면 공개 클라이맥스).
- ✅ **학습 장치**: 플릭 세기 게이지(약함/딱 좋음/셈), 튜토리얼 손님의 적정 구간 표시, 잔열 안내.
- ⚠️ 실기기 체감 확인 필요: 흔들기/플릭 임계값(5 / 13~26 m/s²)은 일반적인 스마트폰 가속도 범위를 기준으로 잡았다. 기기별 편차가 크면 `www/js/motion.js`, `www/js/scenes/cook.js`의 `FLIP` 상수로 조정.

## 3. 발견·수정한 오류
| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 양배추 단계에서 프레임이 수 초씩 멈춤 | 조각마다 `ctx.filter = blur()` 그림자 → 소프트웨어 렌더링에서 매우 느림 | 블러 제거, 미리 그린 그림자 텍스처/접촉 그림자로 교체 (모바일 성능도 개선) |
| 2 | 날것 스테이크인데 79점(★4) | 항목별 합산만 하여 치명적 실수가 묻힘 | 날것 58 / 과조리·과염 62 / 탐 70 점수 상한 도입 |
| 3 | 결과 화면 점수 막대가 비어 보임 | inline `span`에 width 적용 안 됨 | `display:block` |
| 4 | 결과 카드의 버튼이 화면 밖 | 상세 내역 아래에 배치 | 버튼을 코멘트 바로 아래로 이동 |
| 5 | 힌트 문구가 게이지·버튼·쟁반과 겹침 | 고정 위치 | 하단 버튼 높이를 측정해 위에 배치, 플레이팅은 상단 배치 |
| 6 | 플레이팅 쟁반과 하단 버튼 겹침 | 버튼이 두 줄로 줄바꿈 | 버튼 영역 실측 기반 쟁반/접시 배치, 라벨 축약 |
| 7 | 팬 위 측면 색 띠가 위아래 뒤집혀 표시 | 온도 배열 인덱스 방향 오류 | 아래(팬 쪽)=index 0으로 수정 |
| 8 | 시간 초과 직후 이전 단계의 지연 전환이 결과 화면을 덮을 수 있음 | `setTimeout` 경합 | 결과 화면/시간초과 상태에서는 단계 전환 무시 |
| 9 | 탄 고기가 덜 타 보임 | 볼륨 하이라이트가 밝게 덮음 | 탈수록 윤기·하이라이트 감소, 숯 오버레이 |
| 10 | Android CI 빌드 실패 | `setup-android` 액션 오류 | 러너 내장 SDK 사용 |

## 4. 플랫폼 체크리스트
- [x] 세로 고정 (흔들어도 화면 회전 안 함) — AndroidManifest `screenOrientation=portrait`, iOS `UISupportedInterfaceOrientations`
- [x] iOS 모션 권한: 손님 선택 탭(사용자 제스처) 안에서 `DeviceMotionEvent.requestPermission()` 호출, 거부 시 터치 대체 안내
- [x] 센서 없는 기기/PC: 화면 문지르기(흔들기), 위로 쓸어올리기(플릭) 대체 입력
- [x] 앱이 백그라운드로 가면 타이머·지글 소리 정지
- [x] 안내 카드를 읽는 동안 타이머 정지
- [x] 진동: Capacitor Haptics(iOS/Android), 미지원 시 `navigator.vibrate`
- [x] 노치/홈바 safe-area 대응
- [ ] 실기기 테스트(가속도 임계값 미세조정) — 빌드된 APK로 확인 권장

## 6. 가게 경영 모드 검증 (추가)
- 단위 테스트 8개 추가(`tests/economy.test.mjs`, 총 29개 통과): 평판↑ → 적정가↑, 이익은 적정가 근처에서 최대, 폭리 시 만족도·평판 하락, 확장 조건(자금·평판·메달), 대회 상금·명성(손님 ×1.4 이상)·쿨다운, 명성 만료, 요리·단가 단계 증가, 손님 생성.
- 자동 플레이: 새 가게 → 영업 → 87점 → 정산(손님 36명, 이익 ₩453,600, 평판 50→59) → 저장 반영(2일차) → 메뉴판 가격 조정 → 대회 목록까지 콘솔 에러 0건.
- 장기 밸런스 시뮬레이션: 매일 88점 + 적정가 운영 시 약 9~12일 만에 최고 단계. 폭리(+40%)는 평판이 50에 묶여 확장 불가. 75점 플레이는 대회 입상 전까지 2단계에 머묾.
- 수정: 메뉴판 반응 이모지가 만족도 감점과 어긋나던 문제 → 만족도 효과 기준으로 통일.
